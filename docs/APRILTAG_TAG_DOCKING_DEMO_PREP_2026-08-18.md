# AprilTag 定点停靠演示：次日场地准备与验收清单

## 目的与边界

演示目标：操作员指定一个 `tag52h13` ID 后，LIMO 在已建图的矩形试验场内到达该 Tag 所在测试物体的可见面；停车时相机正对 Tag，并满足设定的相机到 Tag 平面距离。

本轮暂不验收：自由环境自主避障、通用物体识别准确率、抓取、机械臂或夹爪动作。

本文件是场地和软件准备清单，不解除当前底盘零运动限制，也不授权任何实时 ROS、底盘、机械臂或夹爪动作。首次真实运动前仍须按现场授权和急停流程执行。

## Tag 编号与摆放

### 固定场地基准 Tag

| 场地边 | family | ID | 安装要求 |
| --- | --- | --- | --- |
| 上边中点 | `tag36h11` | 0 | 垂直、朝场地内部 |
| 右边中点 | `tag36h11` | 1 | 垂直、朝场地内部 |
| 下边中点 | `tag36h11` | 2 | 垂直、朝场地内部 |
| 左边中点 | `tag36h11` | 3 | 垂直、朝场地内部 |

每张基准 Tag 的正面法向必须指向场地内部。量取并记录每张 Tag 中心在 `map` 坐标中的 `(x, y, z, yaw)`；不要把可移动物体 Tag 写入固定地图锚点表。

### 可移动矩形测试物体

每个物体的四个**侧面**各贴一张垂直 Tag，Tag 正面朝外；顶部不纳入本轮目标面。三物体均使用 `tag52h13`：

| 物体 | Tag ID |
| --- | --- |
| 物体 0 | 0、1、2、3 |
| 物体 1 | 4、5、6、7 |
| 物体 2 | 8、9、10、11 |

所有物体共用唯一侧面顺序，不允许现场重新解释：

| `id % 4` | side label | 物体 0 | 物体 1 | 物体 2 |
| --- | --- | --- | --- | --- |
| 0 | `front` | 0 | 4 | 8 |
| 1 | `right` | 1 | 5 | 9 |
| 2 | `back` | 2 | 6 | 10 |
| 3 | `left` | 3 | 7 | 11 |

机器关系固定为 `object_id = id // 4`、`side_index = id % 4`。交换、重复、缺失、列表置换、
`side_0...side_3` 或布尔 ID 均须在离线门中拒绝，不能留到现场靠人工解释。

每张 Tag 必须平整、无反光膜、无遮挡、中心高度与相机高度尽量接近。记录每个物体的实际外形尺寸；测试期间不得移动物体或基准 Tag。

## 推荐尺寸与场地条件

- 场地基准 Tag：外黑边建议 `180–200 mm`；相机到 Tag 超过 3 m 时优先 200 mm。
- 物体 Tag：建议 `120–160 mm`；先保证在 0.5–1.0 m 可稳定检测，再决定是否缩小。
- 四个固定 Tag 应形成已测量的长方形，不要仅靠“贴在中点”推定坐标。
- 无物理围栏不代表无安全约束：在地图中定义矩形虚拟地理围栏、预留墙边和物体周围安全余量；现场安排观察员、可用急停和低速上限。
- 光照稳定；避免强逆光、镜面地面和 Tag 正面反光。

## 停靠目标的精确定义

目标取决于所指定 Tag 的**可见面**。对指定 ID，系统计算该 Tag 的实时位姿，并生成相机停靠位姿：

- 相机光轴与 Tag 正面法向相反，即相机正对 Tag；
- 相机光心到 Tag 平面的距离为 `standoff_m`；
- 使用已标定的 `base_link -> camera` 外参，将相机目标位姿转换为底盘目标位姿。

视觉输出的 camera-frame pose 不能直接改名为 map pose。离线 adapter 必须用同一 observation
SHA、同时间戳 `map -> base_link`/`base_link -> camera` TF、host freshness 与已核验 calibration
SHA 机械计算 `T_map_tag`；规划只接受该 adapter 封存的 `BoundTagPose`。任何外置 `pose_map`、
来源/target 交换、过期、TF 方向或 calibration identity 错配均中止。

adapter 输出必须深不可变，并由 policy 在消费前复算覆盖 target、时间/freshness、confidence、
calibration/source identity 和 map pose 的 canonical digest。现场不得手工编辑 adapter 输出。
`base_link -> camera` translation/orientation 只能由同一份 canonical calibration payload 派生；
配置不得再维护第二份外参数字。即使 SHA 标签正确，只要 TF 几何不同也必须中止。

首次现场验收建议 `standoff_m = 0.40 m`，通过后再依次尝试 `0.30 m`、`0.20 m`。`0.20 m` 指**相机光心到 Tag 平面**，不是车体前缘到物体；必须确认车体前缘、相机最小有效视距和制动余量均允许。

## 分阶段执行

1. **标定和静态观察**：验证四个 `tag36h11` 的 map 位姿、相机内参与 `base_link -> camera` 外参；不移动底盘。
2. **预靠近导航**：目标为 Tag 前方约 `0.8–1.0 m` 的预靠近点；固定场地 Tag 用于定位交叉核验。
3. **视觉精停靠**：仅在目标 `tag52h13` 持续可见时进行最后 `0.5–1.0 m` 的低速闭环；控制横向误差、朝向误差与距离。
4. **保持与记录**：到位后停止，保存目标 ID、Tag 位姿、相机/底盘位姿、最终距离、横向误差、朝向误差和失败原因。

Tag 丢失、姿态不可信、距离异常、超时或围栏预测越界时必须停止并标记失败；不得继续盲走或把失败记录为成功。

## 首轮验收标准

| 项目 | 首轮目标 |
| --- | --- |
| 指定 ID 解析 | 12 个 `tag52h13` ID 均可被唯一映射到对应物体及侧面 |
| 到达前置条件 | 只对可见、未遮挡的目标面执行精停靠 |
| 初始停靠距离 | 相机到 Tag 平面 `0.40 m ± 0.08 m` |
| 正对误差 | yaw `≤ 5°` |
| 横向误差 | `≤ 5 cm` |
| 终止行为 | 成功、超时、Tag 丢失、围栏拒绝均有明确结果；异常时零速度停止 |

在上述标准连续通过后，才把距离改为 `0.30 m`，最后再验证 `0.20 m`。

## 软件接口需求

导航和视觉精停靠应分开。建议新增一个上层动作接口，而不是把精停靠塞进普通导航目标：

`tag_docking_action(target_family, target_id, standoff_m)`

建议状态：`SEARCH -> PREAPPROACH -> ALIGN -> APPROACH -> HOLD -> SUCCESS / ABORT`。

现有导航只负责到预靠近点；新接口接收 Tag 实时位姿并执行最后一段对准。该接口将来可复用于垃圾桶、瓶子或抓取前定位，但本轮只处理 AprilTag。
